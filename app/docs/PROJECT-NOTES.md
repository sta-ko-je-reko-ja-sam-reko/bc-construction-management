# Project Notes — cross-session context

Durable, machine-independent context for this repo. **This file is checked into git**, so it travels to any computer and any Claude Code session that clones the repo — unlike Claude's local memory (`~/.claude/projects/.../memory/`), which is machine-specific and never synced.

**Purpose:** capture decisions, gotchas, and "why we did X" that don't already belong in [CLAUDE.md](../../CLAUDE.md), [PLAN.md](../../PLAN.md), or a feature's `technical-documentation.md`. Keep it terse. When a note becomes a hard rule, promote it to CLAUDE.md; when it's feature-specific, move it into that feature's docs.

- Read this file at the start of work on this repo — it's the portable substitute for local memory.
- Append new cross-session facts here rather than saving them only to local memory.
- Convert relative dates to absolute. Link related feature docs with relative paths.

### 2026-07-03 — Per-feature RapidStart Config. Packages on demo opt-in (demo-data §6)
Implemented §6 of `demo-data-and-import-apis.md`: each feature seeder's `Import()` now also builds a **RapidStart Configuration Package** — so a package exists **only** when the user opts to import that feature's demo data (never eager/on install), idempotent on the package code.
- New shared builder **[CONS Config Package Builder](../src/Setup/ConfigPackageBuilder.Codeunit.al)** (50029): `EnsurePackage(code,name)` (→ `Config. Package Management.InsertPackage(..., ExcludeConfigTables := true)`, returns false if it exists), `AddOwnTable` (all fields), `AddExtendedTable` (adds the standard table, then narrows `Config. Package Field."Include Field"` to **`"Primary Key" OR "Field Name".StartsWith('CONS ')`** — keeps the PK + our affix fields, drops Microsoft's/other extensions' columns). API signatures verified against the BC 28 Base App symbols (8611 in `System.IO`).
- **Tableext fields**: `InsertPackageTable(Database::Job)` enumerates the `Field` table by table id, which **includes** tableextension fields (they carry the base table's id), so our CONS fields on Job/Job Task get package-field rows; the narrow step keeps them. Verified `Config. Package Field` has `Primary Key`(12) + `Field Name`(4).
- **5 packages** (N = features with own demo records): `CONS-FOUNDATION` (ext Job + Job Task), `CONS-ESTIMATING` (own BoQ Header+Line), `CONS-SUBCONTRACTS` (own Subcontract Header), `CONS-EQUIPMENT` (own Equipment), `CONS-SCHEDULING` (own Task Dependency + ext Job Task). Cost Control & Progress Billing seed no own records → **no package** (documented). **Setup tables never packaged.**
- **Data snapshot included**: `SnapshotTable(code, var RecRef)` captures the seeded rows into `Config. Package Data` (one row per included Normal field, values in RapidStart's culture-invariant `Format(value,0,9)`), so each package carries the demo **values**, not just the shape, into another company. Each seeder calls it after creating its records, with a RecRef filtered to the demo rows (Foundation/Scheduling snapshot the extended Job/Job Task too). `Config. Package Data.Value` confirmed `Text[2048]`; `InsertPackageData` signature verified.
- **Permissions**: builder + `Config. Package`/`…Table`/`…Field`/`…Filter`/`…Data` = RIMD added to the shared **`CONS Demo`** set (in `CONS Admin`).

### 2026-07-03 — Effective-permission check made swappable (CONS IAccessPolicy) — proxies pure again
The effective-permission (`UserHasProductAccess`) logic was **copy-pasted** in three places: `CONS Retention Subscribers`, `CONS Subc Base Subscribers`, and `CONS Feature Mgt.HasEffectiveRead`. Applied the `event-subscribers.md` **"Make the access check swappable"** pattern to consolidate it in one place:
- New interface **[CONS IAccessPolicy](../src/Core/IAccessPolicy.Interface.al)** (`HasEffectiveExecute(codeunitId)`, `HasEffectiveRead(tableId)`) + default impl **[CONS Access Policy](../src/Core/AccessPolicy.Codeunit.al)** (50028) — the `PopulatePermissionBuffer`-by-id logic lives here ONCE, `SingleInstance` with per-id `Dictionary` caching.
- Resolved via **[CONS Service Locator](../src/Core/ServiceLocator.Codeunit.al)** (`AccessPolicy()` / `ImplementAccessPolicy()`), so a test/dependent app can inject a different policy.
- **[CONS Retention Subscribers](../src/Retention/RetentionSubscribers.Codeunit.al)** and **[CONS Subc Base Subscribers](../src/Subcontracts/SubcBaseSubscribers.Codeunit.al)** are now **pure proxies** — no globals, no helper, no `System.Security.AccessControl`. Each body: `if not ServiceLocator.AccessPolicy().HasEffectiveExecute(Codeunit::"<reaction impl>") then exit; ServiceLocator.<Reactions>().<Method>(...)`.
- **[CONS Feature Mgt.HasEffectiveRead](../src/Core/FeatureMgt.Codeunit.al)** now one line: `exit(ServiceLocator.AccessPolicy().HasEffectiveRead(TableId))`.

**Critical permission consequence** (per the template): because the proxy calls `ServiceLocator.AccessPolicy()` *before* the guard resolves, the **Service Locator + Access Policy must be executable by everyone** → both added to **`CONS Base Subs`** (Unlicensed-entitled). That means the gate can no longer check the Service Locator (now granted to all) — it checks the **module-gated reaction impl** instead: retention checks `CONS Retention Logic`, subcontracts checks `CONS Subc Wf Reactions` (both only in their module sets). Unentitled users resolve the check (safe — only Microsoft objects touched) and `exit` before the locator ever resolves a licensed reaction. Two-tier gate unchanged: proxy = *owns the module* (effective execute), reaction = *feature enabled* (`IsEnabled`).

### 2026-07-03 — Subc base proxy made polymorphic (consistency with the retention proxy)
Follow-up to the base-subscriber split below. `CONS Subc Base Subscribers` had **inline** business logic in the subscriber bodies (it was a verbatim relocation of the old inline subscribers), whereas `CONS Retention Subscribers` was a clean guard-plus-one-line delegation because Retention already had the interface + Service Locator + logic machinery. Brought Subcontracts up to the same polymorphic shape (`event-subscribers.md` rules 3/5):
- New interface **[CONS ISubc Wf Reactions](../src/Subcontracts/ISubcWfReactions.Interface.al)** and default impl **[CONS Subc Wf Reactions](../src/Subcontracts/SubcWfReactions.Codeunit.al)** (50284) — the 7 approval/workflow bodies moved here; each keeps its `Feature Mgt.IsEnabled(Subcontracts)` guard as its **first line** (the per-feature tier check lives in the logic, not the proxy).
- Registered `SubcWfReactions()` on **[CONS Service Locator](../src/Core/ServiceLocator.Codeunit.al)** (mirrors `RetentionReactions()`), so the impl is swappable in tests/dependent apps.
- **[CONS Subc Base Subscribers](../src/Subcontracts/SubcBaseSubscribers.Codeunit.al)** reduced to pure proxies: each body is `if not UserHasProductAccess() then exit; ServiceLocator.SubcWfReactions().<Method>(...)`. The guard changed from `FeatureMgt.IsEnabled` to an **effective-EXECUTE** check (by object id, never instantiating) on the reaction impl `CONS Subc Wf Reactions` — the licensing/entitlement gate, matching the retention proxy's effective-execute check on the Service Locator. Enablement (feature-on) is now checked only in the logic.
- Added `CONS Subc Wf Reactions` to `CONS Subc - Edit/-Read` (so entitled users have execute → the effective-permission gate passes; unentitled users return early). The proxy stays in `CONS Base Subs` (Unlicensed-entitled). Net: proxy = *does the user own it* (permission), logic = *is the feature on* (Enabled) — the same two-tier split as Retention.

### 2026-07-03 — Demo data: per-feature seeders + MCP-routable import APIs (demo-data pattern)
Implemented the `demo-data-and-import-apis.md` pattern (from `../bc-dev-templates/bc-customer-project-template/al-object-types/_patterns/`). Replaced the single monolithic `CONS Demo Data` codeunit (deleted) with the **full per-feature split** (user's call):
- **7 per-feature seeders** `CONS Demo <Feature>` (50031–50037). `CONS Demo Foundation` owns the shared CONS-DEMO project/customer/vendor/tasks context + fixed-key getters (`EnsureProjectContext`, `DemoProjectCode`, …); the other seeders call it for prerequisites. Cost Control & Progress Billing are documented **context-only** importers (no records of their own). All `Import()` methods are **message-free** (they run from the API/ServiceEnabled path where UI is not allowed) and **fully idempotent via fixed keys** — the document seeders (BoQ `CONS-DEMO-BOQ`, subcontract `CONS-DEMO-SUB`, equipment `CONS-DEMO-EQ1/2`) set `No.` explicitly, so they no longer depend on number series being set up first (the table OnInserts all guard `if "No." <> '' then exit`). This is the template's "fixed keys, not a number series" rule and makes the API path self-sufficient.
- **7 `[ServiceEnabled]` import API pages** `CONS Demo <Feature> API` (50040–50046), each in its **own dedicated `demo<Feature>` API group** (never a functional group), binding to a shared dummy source **table `CONS Demo Data` (50030)**. The bound `importDemoData` action is the deliverable (the MCP tool); the entity/rows are incidental.
- **Per-feature demo MCP configs** — `CONS MCP Demo Config` (50038) builds one MCP configuration per importer (exposing only that feature's demo page), kept separate from the functional `CONS MCP Config Demo` so an agent can be scoped to seed just one feature. Called once (guarded) from `CONS Demo Foundation.Import()` alongside the functional config.
- **Two reach paths, one seeder** (never forked): the assisted-setup wizard (`GuidedSetup.ImportDemoData` case → each `Import()`) and the API/MCP `importDemoData` action both call the same idempotent `Import()`.
- **Permissions**: new shared **`CONS Demo` set (50027)** holds all demo objects; included in **`CONS Admin`** only (seeding writes into every feature's tables, which only the composite grants — demo is an admin/onboarding action). Removed the old monolith codeunit from `CONS Found - Edit/-Read`.
- **Tests**: [DemoDataTests](../../test/src/DemoDataTests.Codeunit.al) (50516) — idempotency + fixed-key/number-series-free seeding for Foundation/Estimating/Equipment/Scheduling.
- **Deviation from prior design**: demo `Import()` no longer pops per-feature `Message()` confirmations (incompatible with the API path); the wizard's Done step provides feedback. Not yet built (no `bcconstr28` container this session) — needs a compile.
